Read Flutter in 5 ideas

Every widget file in your part follows these. Once they click, the files are mostly settings.

1

Everything on screen is a widget

Text, padding, a row, a whole page: all widgets. Even spacing (Padding) and alignment (Center) are widgets that wrap other widgets.

2

Widgets nest like boxes in boxes

One child goes in child:, several go in children: [ ]. The deep indentation in your files is just this nesting. Read it as a tree, from the outside in.

3

build() returns the tree

Flutter calls build whenever it needs to draw. It looks at the current data and returns widgets. It never "changes" the screen; it describes it again.

4

Stateless draws inputs; Stateful also has memory

TaskCard is Stateless: same task in, same card out. TaskListTab is Stateful: it remembers _tasks, and its memory lives in a second class (_TaskListTabState).

5

setState = change memory, then redraw

Change a variable inside setState(() { … }) and Flutter calls build again with the new value. Without setState, the variable changes but the screen doesn't.

class _HomeScreenState extends State<HomeScreen> {
  late final ApiService _api = widget.api ?? ApiService();

_api is the object that makes HTTP calls. It's shared with all three tabs.

_version is a trick. Every tab gets a key that includes this number. After you add a task, the number goes up, so every key changes. Flutter treats a widget with a new key as a brand-new widget, so all three tabs start over and reload their lists.

Future<void> _load() async {
  try {
    final tasks = await widget.api.getTasks(widget.filter);
    if (!mounted) return;
    setState(() {
      _tasks = tasks;
      _failed = false;
    });
  } on ApiException catch (e) {
    if (!mounted) return;
    setState(() => _failed = true);
    showApiError(context, e);
  }
}

Success: save the tasks and clear the error flag, inside setState, so the list appears.
Failure: set _failed and show a red snackbar message (showApiError).

if (!mounted) return; appears twice. The request can take a few seconds, and meanwhile the user may have left this screen. Calling setState on a widget that's gone is an error, so we stop.

Syntax in this part
try { … } on ApiException catch (e) { … }
Run the code. If it throws an ApiException, jump to the on block with the error in e.
mounted
true while this widget is still on screen.
setState(() { a; b; })
Several changes, one redraw.

/// D-46: wait for the server, then reload, so the list always matches the API.
Future<void> _toggleDone(Task task, bool done) async {
  if (_busy.contains(task.id)) return; // ignore double taps
  setState(() => _busy.add(task.id));
  try {
    await widget.api.setDone(task.id, done);
    await _load();
  } on ApiException catch (e) {
    if (mounted) showApiError(context, e);
  } finally {
    if (mounted) setState(() => _busy.remove(task.id));
  }
}
  1. Already busy with this task? Ignore the tap. This stops a double tap from sending two requests.
  2. Mark it busy, so the card shows a small spinner instead of the checkbox.
  3. Tell the server, wait, then reload the list. The screen only changes after the server agrees (decision D-46).
  4. finally always runs, success or error, so the spinner always goes away.
Syntax in this part
finally { … }
Runs after try, whether it worked or threw an error. Used for cleanup.
if (mounted) showApiError(context, e)
Show the error only if we're still on screen.

  • AlwaysScrollableScrollPhysics lets the list be pulled even when there's nothing to scroll.

/// Tasks (already sorted by the API) → headers + tasks, groups in fixed order,
/// a header only when its group has tasks. Order inside a group is kept.
List<ListRow> groupedRows(List<Task> tasks) {
  final byGroup = {for (final g in TaskGroup.values) g: <Task>[]};
  for (final t in tasks) {
    byGroup[groupOf(t.daysLeft)]!.add(t);
  }
  return [
    for (final g in TaskGroup.values)
      if (byGroup[g]!.isNotEmpty) ...[
        HeaderRow(g),
        for (final t in byGroup[g]!) TaskRow(t),
      ],
  ];
}
  1. Make an empty bucket for each group: {overdue: [], today: [], tomorrow: [], thisWeek: [], later: []}.
  2. Put each task into its bucket using groupOf(daysLeft).
  3. Walk the groups in order. For each non-empty group, add a header and then its tasks.

/// A reply with an unexpected shape (missing field, wrong type) becomes a normal
/// [ApiException], so screens show "Something went wrong" instead of spinning forever.
T _parse<T>(T Function() read) {
  try {
    return read();
  } on TypeError {
    throw const ApiException(0, ApiException.genericMessage);
  } on NoSuchMethodError {
    throw const ApiException(0, ApiException.genericMessage);
  }
}

If the JSON has the wrong shape, fromJson throws a TypeError. Without this, the screen would spin forever. With it, the user sees "Something went wrong".

Future<dynamic> _send(String method, String path, [Object? body]) async {
  final request = http.Request(method, Uri.parse('$_base$path'));
  request.headers['Accept'] = 'application/json';
  if (body != null) {

const FILTERS = ["week", "all", "done"];

/** Task list for user `me` (SPEC §4.3). */
async function listTasks({ me, today, filter }) {
  let where = {};
  if (filter === "week") {
    // Not done by me AND due on or before today + 7 (includes every overdue task).
    where = { dueDate: { lte: fromDateStr(addDays(today, 7)) }, done: { none: { userId: me } } };
  } else if (filter === "done") {
    where = { done: { some: { userId: me } } };
  }

  const tasks = await prisma.task.findMany({
    where,
    include: { course: true, done: { where: { userId: me } } },
    orderBy: [{ dueDate: "asc" }, { id: "asc" }],
  });

  if (filter === "done") {
    // Most recently finished first (Prisma can't order by a filtered relation's field).
    tasks.sort((a, b) => b.done[0].doneAt - a.done[0].doneAt || b.id - a.id);
  }
  return tasks.map((t) => toTaskListItem(t, today));
}

/** Idempotent (D-16). Returns false if the task doesn't exist. */
async function markDone(me, taskId) {
  try {
    await prisma.taskDone.upsert({
      where: { userId_taskId: { userId: me, taskId } },
      create: { userId: me, taskId },
      update: {}, // already done: keep the original done_at
    });
    return true;
  } catch (err) {
    if (err.code === "P2003") return false; // foreign key: task (or user) doesn't exist
    throw err;
  }
}

/** Idempotent: undoing something not done is fine. */
async function unmarkDone(me, taskId) {
  await prisma.taskDone.deleteMany({ where: { userId: me, taskId } });
}

upsert: insert the (user, task) row, or do nothing if it's already there, keeping the original time. Error P2003 means the task doesn't exist, so the route answers 404.

const DAY_MS = 24 * 60 * 60 * 1000;
const BANGKOK_OFFSET_MS = 7 * 60 * 60 * 1000; // Asia/Bangkok is UTC+7, no daylight saving

/** Today's date in Bangkok as "YYYY-MM-DD". Pass `now` in tests. */
function todayBangkok(now = new Date()) {
  return new Date(now.getTime() + BANGKOK_OFFSET_MS).toISOString().slice(0, 10);
}

Bangkok is always UTC+7 (no daylight saving). Add 7 hours to the current UTC time and take the date part. At 01:00 in Bangkok it's still yesterday in UTC, and this gets it right.

/** Whole days from `from` to `to` (both "YYYY-MM-DD"). Negative if `to` is earlier. */

Check yourself

Questions a teacher could ask in your demo. Try to answer before opening.

Why does _load() check mounted before setState?

The request takes time. If the user left the screen meanwhile, the widget is gone, and calling setState on it is an error.

What does _version in HomeScreen do?

It's part of each tab's key. Bumping it gives the tabs new keys, so Flutter rebuilds them from scratch and they reload.

Why is the empty message inside a ListView?

RefreshIndicator only works with something scrollable. The ListView (always scrollable, full height) makes pull-to-refresh work on an empty or failed tab.

Why does TaskCard get functions instead of calling the API?

The parent owns the data (lifting state up). The card only draws and reports taps, so it's simple and easy to test.

Where does days_left come from? Why not compute it in the app?

From the server, using Bangkok "today". The phone's clock or time zone could be wrong, and the server is the rule.

What happens on a fast double tap of the checkbox?

The second tap is ignored: _busy already contains the id. On the server the call is idempotent anyway.

Row vs Column vs Expanded?

Row = horizontal, Column = vertical, Expanded = "this child takes the leftover space".

StatelessWidget vs StatefulWidget in your files?

Stateful: HomeScreen (_version), TaskListTab (_tasks, _failed, _busy). Stateless: TaskCard, GroupHeader, EmptyState, TypeChip. They just draw their inputs.
